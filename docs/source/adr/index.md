# 設計判断の記録 (ADR)

開発規則・ツール構成・依存の採否・アーキテクチャなど、後から「なぜそうしたのか」を問われる判断を Architecture Decision Record (ADR) として残します。規則そのものは CONTRIBUTING.md に書き、その **理由と検討した選択肢** をここに記録します。

## 運用

- 新しい ADR は `uv run invoke adr <slug> --title "<タイトル>"` で作成します(採番とテンプレート展開が自動で行われ、このページの一覧にも自動で載ります)。
- ステータスは次のいずれかです。
  - **提案中**: 議論中で、まだ効力を持たない
  - **採用**: 現在有効な判断
  - **廃止**: 判断を取り下げた(代替なし)
  - **NNNN により置換**: 新しい ADR で上書きされた
- 採用済みの ADR は本文を書き換えず、判断を変える場合は新しい ADR を作成して旧 ADR のステータスを「NNNN により置換」に更新します。
