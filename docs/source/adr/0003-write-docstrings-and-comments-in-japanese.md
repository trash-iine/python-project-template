# 0003. docstring とコード内コメントは日本語で書く

- 日付: 2026-09-11
- ステータス: 採用

## 背景

テンプレート作成時の docstring とコード内コメントはすべて英語だった。一方でこのテンプレートを使う開発者は日本語話者であり、README・CONTRIBUTING.md・PR の説明文はすでに日本語で書かれている。説明の言語がコード内と周辺ドキュメントで食い違っており、コードを読むときだけ英語に切り替わる状態になっていた。

英語で書き続ける場合、説明の精度が書き手の英語力に律速される。特に `Args:` の引数説明や設計上の注意を書いたコメントは、曖昧な英語よりも正確な日本語の方が情報量が多い。一方で識別子やコミットメッセージまで日本語にすると、ツール・エコシステムとの相性(補完・grep・git ホスティングの表示)が悪化する。どこに境界を引くかを決める必要があった。

## 検討した選択肢

- **すべて英語のまま維持する**: エコシステムとの相性は最良で、Ruff の docstring ルール(D400 / D401 / D403 / D415)もそのまま使える。ただし説明の精度が書き手の英語力に依存し、README・CONTRIBUTING.md が日本語である以上、読み手は言語を切り替え続けることになる
- **コード中の文字列リテラルも含めてすべて日本語にする**: 一貫性は最も高いが、例外メッセージやログ出力が日本語になると doctest の期待値や CI ログが実行環境のロケール・フォントに依存し、検索したときに英語の事例に当たらなくなる
- **説明は日本語、機械が扱う名前は英語に分ける**: docstring・コメント・ユーザー向けドキュメントを日本語にし、識別子・コミットメッセージ・ブランチ名・コード中の文字列リテラルは英語に保つ

## 決定

3 つ目を採用する。境界は「人間が読むための説明は日本語、機械が扱う名前と出力は英語」とし、CONTRIBUTING.md の「言語ポリシー」節に規則として記載した。

- 日本語: docstring、コード内コメント、README、`docs/source/` の解説ページ、PR / MR の説明文、Issue、レビューコメント
- 英語: 識別子、コミットメッセージ、ブランチ名、例外メッセージなどコード中の文字列リテラル、AGENTS.md(AI エージェント向けのため)

docstring は Google スタイル(Napoleon)を維持し、セクション見出し(`Args:` / `Returns:` / `Raises:` / `Examples:`)は英語のままとする。要約行は「〜する。」の形で終える。

## 結果

- Ruff の D400 / D401 / D403 / D415 を `pyproject.toml` で無効化した。いずれも英語 docstring を前提としたヒューリスティック(末尾ピリオド・命令形・先頭語の大文字化)で、日本語の要約行に対しては誤検知しかしないため
- `Args:` の引数漏れは D417 が引き続き検出する。`Args:` セクション自体の有無はツールで検出できないため、レビューで確認する
- 文字列リテラルを英語に残したことで、doctest(`--doctest-modules`)の期待値と CI ログが実行環境に依存しない
- AGENTS.md は英語のまま維持する。言語ポリシー自体も AGENTS.md に英語で要約されており、規則を変えるときは CONTRIBUTING.md と同一 PR で同期させる
