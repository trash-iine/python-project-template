# 0005. テンプレートから py.typed マーカーを外す

- 日付: 2026-09-11
- ステータス: 採用

## 背景

`src/sample_project/` に空の `py.typed` を置いていた。PEP 561 のマーカーで、「このパッケージの型情報は配布物に含まれており、利用側の型チェッカーが参照してよい」ことを宣言するものである。

しかしこのリポジトリはライブラリではなくプロジェクト雛形であり、PyPI などへの配布を前提としていない。派生プロジェクトが必ずライブラリになるとも限らない(CLI やアプリケーションの方が多い想定である)。マーカーが既定で入っていると、型情報を配布する意図がないパッケージにも「配布する」という宣言だけが残り、README のディレクトリ構成にも「型情報配布マーカー(PEP 561)」という説明が載り続ける。

## 検討した選択肢

- **`py.typed` を残す**: 派生プロジェクトがライブラリとして配布される場合に追加し忘れがない。ただし配布しないプロジェクトでは意味のない宣言が残り、テンプレートの既定として誤った前提を与える
- **`py.typed` を削除する**: 既定を「型情報を配布しない」に倒す。ライブラリとして配布するプロジェクトでは、その時点で空ファイルを 1 つ置けば済む

## 決定

2 つ目を採用し、`src/sample_project/py.typed` を削除した。README のディレクトリ構成からも該当行を除いた。

テンプレートの既定は「配布しない」とする。ADR 0004 で定めた「必要十分」の設計方針(具体的な利用者が現れるまで導入しない)を、配布設定にも適用した形である。

## 結果

- 派生プロジェクトをライブラリとして配布する場合は、パッケージ直下に空の `py.typed` を追加し、ビルド設定に含まれることを確認する必要がある
- 型ヒント自体の規則(具体型優先・抽象化機構の制限)は ADR 0004 のとおり変更しない。型を書かなくなったわけではなく、書いた型を配布物として公開しないという判断である
